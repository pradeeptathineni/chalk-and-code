This is the path I take students along, usually starting in grade school. Every idea shows up three times: first as blocks you snap together, then in Scratch where you can make a game out of it, and then as a few lines of Python. By the time a student types their first `for` loop, they already know what a loop *is*, because they have built one with their hands.

| # | Unit | What it covers | Tools | Grades | Status |
|---|---|---|---|---|---|
| 1 | Telling a computer what to do | instructions in order, debugging by acting it out, "unplugged" games with cards and arrows | paper, Blockly | K–3 | Planned |
| 2 | Loops and patterns | repeat blocks, spotting the pattern, drawing shapes with loops | Blockly, Scratch | 2–5 | Planned |
| 3 | Events and games | "when clicked", keys, sprites that talk to each other, a first game | Scratch | 3–6 | Planned |
| 4 | Decisions and variables | if / else, keeping score, a timer, random numbers | Scratch | 3–6 | Planned |
| 5 | From blocks to Python | the same programs as text: `print`, variables, `if`, `for`, `while` | Python | 5–8 | Planned |
| 6 | Functions and your own tools | naming a set of steps, inputs and outputs, reusing your code | Python | 6–8 | Planned |
| 7 | Making things move | drawing and animation with p5.js; a bouncing ball with real gravity | p5.js | 6–8 | Planned |

Two other tracks pick up from here: [Robots](../robots/index.md), where your Python program drives a real robot, and [Physics](../physics/index.md), where the animation loop `v += a·dt; x += v·dt` turns out to be the same idea as the equations of motion, done one small step at a time.
